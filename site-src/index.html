Museumwright

A museum's archive, built from what a family kept.

mw writes a museum's records from a web page, a folder of files or a phone's photographs; checks every save against the museum's rules; and runs the museum on its own box, on its own network, with or without the web.

See a demo museum The code

Install, then five commands

npm install -g github:ajcali086/Museumwright-
mw doctor          # is this box ready? what's missing, and the command that fixes it
mw new            start a museum (asks a few questions)
mw pull <url>     bring in a web page
mw add <folder>   bring in files: photos, PDFs, text
mw desk           open the curator's desk on this box's network
mw sync           trade commits with GitHub

No flags needed; every refusal in plain words. mw desk prints the address to open and, the first time, a setup code. Visitors on the network see the museum; the curator builds the archive at the desk, in three stages:

  1. Collection. Create the museum; add a page from the web, files from the box, or photographs from a phone.
  2. Archival work. Decide the names a local model noticed, each shown in the words that spell it; catalogue, correct, link evidence, open questions, retire. Every change is shown before it is written, and the museum's own check decides whether it stays.
  3. Site. What visitors see, rebuilt after every change; the history in git on the box, sent to GitHub when the web is there.

What it holds to

  • A caption or credit is the source's, word for word, or empty: never invented.
  • A name the machine noticed is a proposal, not an entity, and its passage must spell it.
  • IDs are claimed once; the same input gets the same IDs; a retired ID is never reissued.
  • What visitors see has no path to what is still undecided.

The demo is built by mw during each deploy, from a local copy of a page in the tests. It is read-only: the desk runs on a museum's own box, not here.
